# atlas-replication

**Status:** Seeded. Implements `atlas::replication::write_entity_ref` and `atlas::replication::read_entity_ref` (`include/atlas/replication/entity_ref_codec.hpp`) — a matched encode/decode pair that puts `atlas::EntityRef` on the wire as an explicit little-endian `index` field followed by an explicit little-endian `generation` field, built on `atlas::serialization::ByteWriter`/`ByteReader` rather than a memcpy of `EntityRef`'s native layout. `read_entity_ref` fails explicitly (`std::nullopt`) if either field is truncated, the same past-the-end behavior `ByteReader` already gives every fixed-width read. Nothing else in this library's eventual scope (property replication strategies, resource/state replication, delta compression, network transport) is implemented yet.

**Scoping decisions:**
- This is deliberately the smallest real slice of "state synchronization" that stands on its own: naming an entity on the wire is the prerequisite for replicating anything *about* that entity (spec §6, Server Authority: "Replication distributes observable state from authoritative hosts" — there is no observable state about an entity without first being able to identify the entity). Everything downstream of this is out of scope for this round.
- Property replication strategies ("replicate contributions" vs. "replicate effective value", spec §20 Networking and Replication) are explicitly deferred: they're properties of the not-yet-existing property composition system, and inventing a replication strategy ahead of the mechanism it replicates would be speculative.
- Actual network transport/delivery (sockets, connections, reliability) is explicitly out of scope per spec §13 — `atlas-replication`'s responsibility is the replication *mechanism* (what goes on the wire and how it's framed), not networking I/O.
- Wire format is `index` then `generation`, each a plain `u32` — no varint/delta encoding, no bit-packing. `EntityRef`'s two fields are already fixed-width `uint32_t`, so anything more elaborate would be premature optimization ahead of a real usage site; a future capability-composed replication frame can wrap this codec however it needs to.
- The two functions take `ByteWriter`/`ByteReader` directly (no `EntityRef`-specific stream type) — consistent with how atlas-serialization's own fixed-width `write_*`/`read_*` calls compose into whatever larger buffer a caller is building, letting `write_entity_ref`/`read_entity_ref` sit inline in a larger message alongside other fields without their own framing.

**Provides:** state synchronization, replication mechanisms, network data distribution.

**Spec:** [§13 Library Architecture](../../docs/specification/13-library-architecture.md#library-responsibilities) (responsibility), [§6 Server Authority](../../docs/specification/06-server-authority.md) (Request Validation and Reconciliation — "confirm / replicate new state", the reason entity identity needs to cross the wire at all), [§20 Property and Resource Composition](../../docs/specification/20-property-and-resource-composition.md#networking-and-replication) (property replication strategies, deliberately deferred), [§4 Architectural Invariants](../../docs/specification/04-architectural-invariants.md) (deterministic execution — the reason encoding is explicit-endianness rather than native-layout)

## Dependency position

`atlas-replication` depends on `atlas::entity` (for `EntityRef`) and `atlas::serialization` (for `ByteWriter`/`ByteReader`), both linked `PUBLIC` since the codec's public header exposes both types directly, plus `atlas_project_options`/`atlas_project_warnings` and the standard library. Per §5, it may depend on further lower-level libraries and generated contracts as replication's scope grows, never upward on capabilities, applications, or editor/deployment-specific code.
